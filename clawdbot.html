1. Preparação do Sistema

Vamos preparar seu Synology DS224+ para rodar o Clawdbot com máxima eficiência. Com 6GB de RAM, você tem recursos excelentes para esta aplicação.

📋 Verificações Iniciais:
• DSM 7.2+ instalado e atualizado
• Container Manager instalado
• Pelo menos 2GB de espaço livre
• Conexão estável com internet

1.1 Instalação do Container Manager

  1. Acesse o Package Center no menu principal do DSM
  2. Busque por "Container Manager" na barra de pesquisa
  3. Instale o pacote e aguarde a conclusão (2-3 minutos)
  4. Verifique a instalação abrindo o Container Manager

1.2 Especificações do Seu Sistema

Seu DS224+ tem configuração ideal para o Clawdbot:

  • Processador: Intel Celeron J4125 (4 cores, 2.0-2.7GHz) ✅
  • RAM: 6GB DDR4 ✅ Excelente!
  • Arquitetura: x86_64 ✅ Compatível
  • Docker: Suporte nativo completo ✅

2. Configuração da API Groq

O Groq oferece acesso ao Llama 3.1 com velocidade excepcional (250-300 tokens/segundo) e tier gratuito generoso.

🚀 Por que Groq?
• Velocidade: 100x mais rápido que modelos locais
• Custo: $0.05-0.59 por milhão de tokens
• Tier gratuito: 14.400 requisições diárias
• Zero impacto no seu NAS

2.1 Criação da Conta

  1. Acesse: console.groq.com
  2. Cadastre-se usando Google, GitHub ou e-mail
  3. Confirme seu e-mail através do link enviado
  4. Complete o perfil com informações básicas

2.2 Gerando a API Key

  1. Vá em "API Keys" no menu lateral
  2. Clique em "Create API Key"
  3. Nome: "Clawdbot-DS224"
  4. Copie e guarde a chave (será exibida apenas uma vez!)
⚠️ CRÍTICO: Sua API key é como uma senha do banco. Nunca compartilhe publicamente. Se comprometida, revogue imediatamente.

2.3 Modelos Disponíveis

Modelos Groq Recomendados 
llama-3.1-8b-instant    → Tarefas simples e rápidas  ($0.05/1M tokens)
llama-3.1-70b-versatile → Análises complexas       ($0.59/1M tokens)
llama-3.2-3b-preview    → Balanço custo/performance ($0.06/1M tokens)

3. Estrutura de Diretórios

Vamos criar uma estrutura organizada que facilita manutenção, backups e troubleshooting.

3.1 Estrutura Completa

Árvore de Diretórios 
/volume1/docker/clawdbot/
├── config/              # Configurações (.env, soul.md)
├── data/                # Memória persistente do bot

3.2 Criação via File Station

  1. Abra o File Station no menu principal
  2. Navegue até volume1 e localize/crie a pasta "docker"
  3. Crie a pasta "clawdbot" dentro de docker
  4. Crie as subpastas: config, data, logs, skills, backups
  5. Dentro de data, crie: conversations, memory, cache

3.3 Criação via SSH (Opcional)

create-structure.sh 
#!/bin/bash

# Script para criar estrutura completa do Clawdbot
BASE_DIR="/volume1/docker/clawdbot"

echo "Criando estrutura para Clawdbot..."

# Criar diretórios
sudo mkdir -p "$BASE_DIR/config"
sudo mkdir -p "$BASE_DIR/data/conversations"
sudo mkdir -p "$BASE_DIR/data/memory"
sudo mkdir -p "$BASE_DIR/data/cache"
sudo mkdir -p "$BASE_DIR/logs"
sudo mkdir -p "$BASE_DIR/skills"
sudo mkdir -p "$BASE_DIR/backups"

# Definir permissões
sudo chown -R $(whoami):users "$BASE_DIR"
sudo chmod -R 755 "$BASE_DIR"

echo "✅ Estrutura criada com sucesso!"

4. Configuração Docker Compose

O arquivo docker-compose.yml define como o Clawdbot será executado, otimizado especificamente para seu DS224+ com 6GB RAM.

4.1 Arquivo Principal

docker-compose.yml 
version: '3.8'

services:
  clawdbot:
    image: node:22-bookworm-slim
    container_name: clawdbot
    hostname: clawdbot-ds224
    restart: unless-stopped
    
    volumes:
      - ./config:/app/config
      - ./data:/app/data
      - ./logs:/app/logs
      - ./skills:/app/skills
    
    working_dir: /app
    
    environment:
      - NODE_ENV=production
      - TZ=America/Sao_Paulo
      - LOG_LEVEL=info
      # Otimização para 6GB RAM total
      - NODE_OPTIONS=--max-old-space-size=1536
      - ENV_FILE=/app/config/.env
    
    command: >
      sh -c "
        echo '🚀 Iniciando Clawdbot...' &&
        apt-get update -qq &&
        apt-get install -y -qq git curl &&
        if [ ! -f package.json ]; then
          echo '📦 Clonando repositório...' &&
          git clone https://github.com/clawdbot/clawdbot.git . &&
          echo '📚 Instalando dependências...' &&
          npm install --production --silent
        fi &&
        echo '✨ Iniciando aplicação...' &&
        npm start
      "
    
    ports:
      - "3000:3000"
    
    # Limites otimizados para DS224+ (6GB RAM)
    deploy:
      resources:
        limits:
          memory: 2G        # Deixa 4GB para DSM
          cpus: '2.0'     # Usa 2 dos 4 cores
        reservations:
          memory: 512M
          cpus: '0.5'
    
    healthcheck:
      test: ["CMD", "node", "--version"]
      interval: 60s
      timeout: 10s
      retries: 3

networks:
  default:
    name: clawdbot-network

6. Deploy e Segurança

Com tudo configurado, vamos inicializar o Clawdbot e implementar medidas de segurança essenciais.

6.1 Iniciando o Container

  1. Container Manager → Projeto → clawdbot
  2. Clique em "Iniciar" ou "Build"
  3. Aguarde 3-5 minutos (primeira inicialização)
  4. Monitore os logs na aba "Log" do container

6.2 Configuração de Segurança

Firewall do DSM

  1. Painel de Controle → Segurança → Firewall
  2. Ative o firewall se não estiver habilitado
  3. Crie regra: Permitir porta 3000 apenas da rede local
  4. Bloqueie acesso externo direto à porta 3000

Reverse Proxy (HTTPS)

  1. Painel de Controle → Portal de Aplicativos → Proxy Reverso
  2. Criar nova regra:
    • Origem: localhost:3000
    • Destino: clawdbot.seudominio.synology.me:443
  3. Ative WebSocket nas configurações avançadas
  4. Configure certificado SSL (Let's Encrypt recomendado)

6.3 Script de Backup Automático

backup-clawdbot.sh 
#!/bin/bash

# Backup automático do Clawdbot
SOURCE_DIR="/volume1/docker/clawdbot"
BACKUP_DIR="/volume1/docker/clawdbot/backups"
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_NAME="clawdbot_backup_${DATE}.tar.gz"

echo "🔄 Iniciando backup do Clawdbot..."

# Criar backup
tar -czf "${BACKUP_DIR}/${BACKUP_NAME}" \
    -C "$SOURCE_DIR" \
    --exclude='data/cache/*' \
    --exclude='logs/*.log' \
    config/ data/ skills/

if [ $? -eq 0 ]; then
    echo "✅ Backup criado: ${BACKUP_NAME}"
    
    # Limpar backups antigos (>30 dias)
    find "$BACKUP_DIR" -name "clawdbot_backup_*.tar.gz" -mtime +30 -delete
    echo "🧹 Backups antigos removidos"
else
    echo "❌ Erro no backup!"
    exit 1
fi

6.4 Agendamento do Backup

  1. Painel de Controle → Agendador de Tarefas
  2. Criar → Tarefa agendada → Script definido pelo usuário
  3. Configurar:
    • Nome: Backup Clawdbot
    • Usuário: root
    • Agendamento: Diário às 3:00 AM
  4. Cole o script na área de comando

#!/bin/bash

# Teste da conexão Groq
API_KEY="sua_chave_groq_aqui"

echo "🧪 Testando conexão com Groq..."

curl -X POST "https://api.groq.com/openai/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $API_KEY" \
  -d '{
    "model": "llama-3.1-8b-instant",
    "messages": [{"role": "user", "content": "Responda apenas: Teste OK"}],
    "temperature": 0.5,
    "max_tokens": 10
  }'

echo ""
echo "✅ Se você viu uma resposta JSON, está funcionando!"

7.4 Monitoramento de Recursos

Verifique o uso de recursos no Monitor de Recursos do DSM:

📊 Uso Normal Esperado:
• RAM: 400-800MB (picos até 1.2GB)
• CPU: 1-5% idle, 15-30% durante inferência
• Rede: Variável conforme uso da API
• Disco: Baixo I/O, crescimento gradual dos logs

7.5 Troubleshooting Comum

Container não inicia:

  • Verifique se os arquivos .env e soul.md existem
  • Confirme permissões das pastas (755)
  • Analise logs para erros específicos

API key inválida:

  • Verifique se copiou a chave completa
  • Confirme que não há espaços extras
  • Gere nova chave no console Groq

Respostas lentas:

  • Verifique conexão com internet
  • Force uso do modelo 8B para testes
  • Monitore uso de CPU/RAM do NAS
